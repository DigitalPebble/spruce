# Read and write SPRUCE data on Amazon S3

A few additional steps are needed in order to process data from and to AWS S3. For more details, look at the 
[Spark documentation](https://spark.apache.org/docs/latest/cloud-integration.html).

## Export your AWS credentials

SPRUCE reads the standard AWS environment variables. The simplest way to set them is to let the AWS CLI export
the credentials of one of your profiles

```shell
eval "$(aws configure export-credentials --profile default --format env)"
export AWS_REGION=$(aws configure get region --profile default)
```

This sets `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` and, for temporary credentials (SSO or an assumed role),
`AWS_SESSION_TOKEN`. Temporary credentials expire, so run the command again if you get access errors later on.

`AWS_REGION` should be the region of the bucket holding the data. If you don't know it, ask S3

```shell
aws s3api get-bucket-location --bucket MY_BUCKET
```

An empty or `null` `LocationConstraint` means `us-east-1`.

If you want to write the outputs to S3, make sure the target bucket exists 

```shell
aws s3 mb s3://MY_TARGET_BUCKET
```

## Enrich data on S3

<div class="warning">

You will need to uncomment the dependency

`<artifactId>spark-hadoop-cloud_2.13</artifactId>`

in the file pom.xml in order to be able to connect to S3.
</div>

Spark accesses S3 with the `s3a://` scheme.

### With Spark installed in local mode

You need to recompile the jar file with `mvn clean package`.

then launch Spark in the normal way

```shell
spark-submit --class com.digitalpebble.spruce.SparkJob --driver-memory 8g ./target/spruce-*.jar -i s3a://BUCKET_WITH_CURS/PATH/ -o s3a://OUTPUT_BUCKET/PATH/
```

where `BUCKET_WITH_CURS/PATH/` is the bucket name and path of the input CURS and `OUTPUT_BUCKET/PATH/` the bucket name and path for the output.

### With Docker

After you edit the pom.xml (see above), you need to build a new Docker image

`docker build . -t spruce_s3`

Pass the variables exported above to the container with `-e`. Giving only the name copies the value from your shell,
so the keys never appear on the command line.

```shell
docker run -it --rm --name spruce \
-e AWS_ACCESS_KEY_ID \
-e AWS_SECRET_ACCESS_KEY \
-e AWS_SESSION_TOKEN \
-e AWS_REGION \
-e SPRUCE_DRIVER_MEMORY=8g \
spruce_s3 \
-i s3a://BUCKET_WITH_CURS/PATH/ -o s3a://OUTPUT_BUCKET/PATH/
```

`SPRUCE_DRIVER_MEMORY` is optional and sets the heap given to Spark; see
[Allocating more memory](../tutorial/with-docker.md#allocating-more-memory).

## Report on data from S3

The [report generator](../tutorial/results.md) and the [dashboard](dashboard.md) read enriched data from S3 directly.
They work with the published image as is, so there is no need to rebuild it. Pass the same variables as above.

<div class="warning">

The reporting tools use the `s3://` scheme, not `s3a://`. Use the same bucket and path as the enrichment output,
with `s3://` in front.
</div>

Generate a report; the output file is written to the current directory through the mounted volume

```shell
docker run --rm -v $(pwd):/workspace -w /workspace \
-e AWS_ACCESS_KEY_ID \
-e AWS_SECRET_ACCESS_KEY \
-e AWS_SESSION_TOKEN \
-e AWS_REGION \
ghcr.io/digitalpebble/spruce report -i s3://OUTPUT_BUCKET/PATH/ -o report.html
```

Start the dashboard on [http://localhost:8501](http://localhost:8501)

```shell
docker run --rm -p 8501:8501 \
-e AWS_ACCESS_KEY_ID \
-e AWS_SECRET_ACCESS_KEY \
-e AWS_SESSION_TOKEN \
-e AWS_REGION \
ghcr.io/digitalpebble/spruce dashboard -i s3://OUTPUT_BUCKET/PATH/
```

<div class="warning">

With images for SPRUCE 1.5 and earlier, reading from S3 fails with
`Can't find the home directory at '/nonexistent'`. Add `-e HOME=/tmp` to the commands above to work around it.
The container then downloads the DuckDB extensions it needs at startup, so it requires access to the internet.
</div>
